# **100 台 iPhone 集群控制 PCB 硬件与软件架构方案**

**目标：设计一套可扩展的 iPhone USB-C 集群控制系统，实现 100 台苹果手机同时连接、快速充电、数据通信、独立编号、桌面端集中管理，以及多块 PCB 互联。**

建议采用 **分布式 PCB 模块 + USB 3.x 数据总线 + USB-PD 独立供电 + 以太网控制网络 + 桌面管理系统**。

## **二、核心硬件配置**

| 项目       | 建议配置                           |
| -------- | ------------------------------ |
| PCB 数量   | 10 块，每块控制 10 台                 |
| 手机接口     | 100 × USB-C                    |
| USB 上行接口 | 每板 2 个，分别管理 5 台                |
| 网络接口     | 每板 2 × RJ45，建议 2.5GbE          |
| 供电       | 每手机接口独立 USB-PD                 |
| 充电能力     | 标准方案每口 45W 设计预算                |
| 设备编号     | PCB-ID + PORT-ID + iPhone 设备标识 |
| 单口管理     | 通断电、连接检测、电流电压、异常告警             |
| 板间通信     | 千兆/2.5G Ethernet，通过交换机汇聚       |
| 扩容方式     | 添加 PCB、计算节点和供电模块               |

这里有一个必须明确的技术区别：**PCB 上的 RJ45 网口不能直接代替连接电脑的 USB 数据接口。** 如果需要从网线远程访问 USB 设备，就必须增加板载 USB 主机及 USB-over-IP 或专用设备代理软件。

## **三、PCB 内部电路设计**

建议每块 PCB 分成四个独立电路区域，减少 USB 高速信号受到电源噪声干扰。

| 电路模块      | 建议器件或技术                | 作用                       |
| --------- | ---------------------- | ------------------------ |
| USB Hub   | 2 × Microchip USB5906C | 每颗管理 5 个手机接口，最高 5Gbps 上行 |
| USB-PD 控制 | 10 × TI TPS25751A      | 每端口独立协商供电，支持 PPS/AVS     |
| 电源转换      | 10 路独立 DC/DC           | 提供所需的 USB-PD 输出电压        |
| 主控 MCU    | STM32 系列或同类工业 MCU      | 端口状态、供电管理、故障保护           |
| 网络控制      | Ethernet 控制器/交换芯片      | PCB 管理、通信与多板组网           |
| 电源保护      | eFuse、TVS、过流与温度检测      | 每路独立保护                   |

USB5906C 是目前在产的六下游端口 USB 3.2 Gen 1 SmartHub，适合采用两个独立五端口数据组。TPS25751A 支持 PD 3.2 与 AVS，但仍需配套设计电源转换、功率路径和完整 USB-C 接口电路，不能单靠控制器芯片实现快充。

建议采用 48V DC 分布式供电，每块 PCB 配独立约 600W 的电源模块，10 块板总配置约 6kW 的供电容量。还需要机架通风、分路保护、过热降额以及总功率限制。

### **关于同步控制和低延迟**

这里要区分两种控制方式：

- **自研 iOS App：** 在应用中部署指令接收模块，使用持久连接、时间戳和预定执行时间，比较适合做批量同步操作。
- **控制其他 iOS App：** 可在开发测试场景使用 Appium + XCUITest + WebDriverAgent，但需要设备信任、开发者模式、签名和相应的测试权限。PCB 本身不能绕过 iOS 限制，直接模拟任意 App 的触摸操作。

  [image](https://www.google.com/s2/favicons?domain=https://appium.github.io\&sz=32)

  Appium XCUITest Driver+2



建议把同步调度放到软件层，采用 `command_id + device_id + execute_at + ack` 协议，提前下发命令，而不是依赖 100 台手机依次收到命令后马上执行。

可以先把自研 App 的跨设备执行偏差不超过 50ms 作为测试目标，但这不是当前能够保证的实际性能；第三方 App 的 UI 自动化延迟通常更难控制，需要单独压测。

## **六、多块 PCB 互联与扩容**

推荐采用两条独立链路：

**数据链路：** 每板两组 USB 上行分别连接指定 Mac 主机，避免所有手机共享一条 USB 总线。初期规划 4 台 Mac 计算节点，实际数量再依据 100 台并发测试的资源占用调整。

**控制链路：** 每块 PCB 通过 Ethernet 连接管理交换机，桌面端统一访问各板。板上第二个网口可用作维护或冗余接口；如需级联，必须设计交换与环路保护，不能简单并接网线。

## **七、开发落地顺序**

1. **第一阶段：2 口 PCB 验证板**

   验证充电与 USB 数据同时工作、PD 协商、每口通断、设备识别和 USB 断线恢复。
2. **第二阶段：10 口 PCB 工程样机**

   加入双 USB 上行、双网口、电源检测、散热及桌面管理软件。执行满载、长时间稳定性和电气兼容测试。
3. **第三阶段：100 台整机集成**

   10 块 PCB 组合成机架系统，完成设备编号、跨板同步、批量通信、异常恢复和持续运行测试。

**最终建议：** 把整套设备定位为“100 台 iPhone USB-C 集中充电与通信控制系统”。硬件负责可靠供电、USB 连接、物理端口管理；Mac 计算节点负责 iOS 通信和自动化；桌面软件负责统一调度和监控。这比尝试用一块 PCB 直接接管所有手机，更容易开发、维护和扩容。

还有一个关键技术条件需要确定：**这 100 台 iPhone 是运行你自己开发的 App，还是需要同步控制微信、浏览器等其他 App 的界面？** 这直接决定软件控制协议、延迟上限和 PCB 是否需要增加板载 USB 主机。
